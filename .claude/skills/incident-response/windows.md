# Incident Response — Windows hosts and Active Directory domain controllers

Version: draft 2026-10-29 (skill-smith). Used with `SKILL.md` in this folder: it replaces, for Windows, the Linux "Expected evidence" table, the step 4 pattern list and the persistence checklist. Steps 1–13, the result values (`İZ VAR`, `İZ YOK`, `KANIT YOK`), the total rule (= 6) and all Limits stay as in `SKILL.md`.

Event IDs, registry locations and GUIDs below are commonly documented values; they were not re-verified from a primary source in this draft. Where a finding depends on what an event ID or setting means, write that meaning as `[DOĞRULANMAMIŞ]` unless a verified source is cited. The collection commands were written, not executed; they are untested.

## Windows expected evidence
The user collects on the host in an elevated PowerShell session, one output per UTF-8 file, then copies the folder to the evidence location. Rules:
- Do not filter outputs (`Select-String`, `findstr`, ad hoc `Where-Object`) unless the table defines the filter. Filtered lists force `KANIT YOK` (DC01 lesson: an 8-row `services.txt` could not support K2).
- Exception for secrets: some keys mix needed values with secrets. For those the table queries named values only (e.g. Winlogon: `/v Userinit`, `/v Shell`), never the whole key.
- Prefer `Format-List` or `Out-String -Width 4096`; `Format-Table` truncates.
- Export event times in UTC: `@{n='TimeUtc';e={$_.TimeCreated.ToUniversalTime().ToString('o')}}`. If local time is exported, write the time zone in `TOPLAMA_NOTU.txt`.
- `MANIFEST.sha256` in `sha256sum` format: `Get-FileHash -Algorithm SHA256 <files> | ForEach-Object { "{0}  {1}" -f $_.Hash.ToLower(), (Split-Path $_.Path -Leaf) }`. Suspicious files are hashed at their original location.
- `<start>` / `<end>` = incident window as `[datetime]` values the user fills in.
- `Get-WinEvent -FilterHashtable` is believed to reject queries with more than about 23 IDs in one `Id` array ("The specified query is invalid"; not verified). Keep each query's ID list short, as in the table, and append with `Export-Csv -Append`.

Never collect (remind the user if present): registry hives (`SAM`, `SECURITY`, `SYSTEM`), `NTDS.dit`, LSASS memory dumps (creating them is credential dumping and is forbidden in the pilot), auto-logon secrets (Winlogon `DefaultPassword`, `AltDefaultPassword`; do not export the whole `Winlogon` key; LSA secrets are not read either), browser password stores, LAPS password attributes, Group Policy Preferences `cpassword` values (if a GPP XML must be reviewed, the user masks `cpassword` before copying), raw `msDS-KeyCredentialLink` values, `Get-ADUser -Properties *`. If one of these is found in the evidence anyway, do not copy the value: write its location (file:line) and type, mask it, and recommend removing it and rotating the secret. Memory and disk images may be taken by the user with dedicated forensic tools; their analysis is outside this skill.

Windows-specific preparation notes:
- `.kanit` removes the file association (no double-click execution); the read-only attribute protects content. Windows has no execute bit.
- Windows Defender may quarantine a `.kanit` copy; the hash checks in steps 2 and 11 detect this.
- Registry values have no per-value timestamp in `reg query` output. A registry-based trace is dated only by an event (4657 from the optional `security_extra.csv`, only if registry auditing with SACLs was on; 4104 script block) or not at all; an undated entry is still [OLGU], its creation time is [DOĞRULANMAMIŞ].
- `Get-AD*` dates are printed in the collector's culture format (e.g. `27.10.2026 02:22:47`). Note the format and time zone in Kapsam.
- Event absence is evidence only if the producing audit subcategory was enabled (`auditpol.txt`) and the export covered that ID and window. Otherwise "0 events" supports neither `İZ VAR` nor `İZ YOK`.

## Static review patterns (step 4, Windows / PowerShell / batch / script files)
Extract with line numbers; never execute, never decode:
- network: IPs, domains, URLs, UNC paths (`\\host\share`), `Net.Sockets.TcpClient`
- download and execute: `IEX`, `Invoke-Expression`, `DownloadString`, `DownloadFile`, `Invoke-WebRequest`/`iwr`, `Invoke-RestMethod`/`irm`, `Net.WebClient`, `Start-BitsTransfer`, `bitsadmin /transfer`, `certutil -urlcache` / `-decode`, `mshta`, `rundll32`, `regsvr32 /i:`, `wmic process call create`, `Start-Process -WindowStyle Hidden`
- PowerShell evasion: `-EncodedCommand` / `-enc` / `-e`, `-w hidden`, `-nop`, `-ep bypass`, `FromBase64String`, `-version 2`, AMSI references (`AmsiUtils`, `amsiInitFailed`)
- persistence writes: `schtasks /create`, `Register-ScheduledTask`, `New-Service`, `sc create` / `sc config`, `reg add` / `New-ItemProperty` / `Set-ItemProperty` on Run, Winlogon, IFEO or `Lsa` keys, `__EventFilter` / `CommandLineEventConsumer` / `Set-WmiInstance`, Startup folder paths, `authorized_keys`, `msDS-KeyCredentialLink`
- account and privilege: `net user /add`, `net localgroup administrators`, `net group "Domain Admins"`, `New-ADUser`, `Add-ADGroupMember`, `Set-ADAccountPassword`, `Set-ADUser -Replace`, `dsacls`, `Add-ADPermission`, `Set-Acl` on `AD:` paths
- credential access (record as [OLGU], never reproduce the technique): `sekurlsa::`, `lsadump::`, `kerberos::golden`, `privilege::debug`, `Invoke-Mimikatz`, `procdump` with `lsass`, `comsvcs.dll` with `MiniDump`, `ntdsutil` with `ifm`, `vssadmin create shadow`, `reg save HKLM\SAM`
- defense and trace removal: `wevtutil cl`, `Clear-EventLog`, `Remove-EventLog`, `auditpol /clear`, `auditpol /set ... /success:disable`, `Set-MpPreference -Disable*`, `Add-MpPreference -Exclusion*`, `fsutil usn deletejournal`, PSReadLine history deletion, timestamp changes (`.LastWriteTime =`, `.CreationTime =`)

Decision rules (Windows):
- `İZ VAR` needs an artifact or a recorded change attributable to the incident window (or undated but clearly malicious-looking, then the dating is [DOĞRULANMAMIŞ]). A configuration weakness alone (WDigest = 1, RDP open to `Any`, no `RunAsPPL`) is not a persistence trace: report it in Bulgular as [OLGU] and route the full audit to `config-auditor` (`windows-dc.md`).
- An access path that existed before the incident and was used to get in (e.g. RDP open to the internet) is the entry vector, not a K4 trace. K4 is `İZ VAR` only if an authorization was added or changed, or a remote access tool was installed, in or after the window. (User decision, 2026-10-29.)
- K6 `İZ VAR` for credential material means: the theft command is in evidence and the secret has not been rotated since. Whether the command succeeded stays [DOĞRULANMAMIŞ] unless evidence shows its output.
- `İZ YOK` needs a complete, unfiltered state listing for the item's main locations (e.g. unfiltered `services.txt` for K2). Missing creation events do not prevent `İZ YOK` if the state listing is complete, but write that a create-and-delete inside the window would not be visible. Named-value queries (e.g. Winlogon in `autostart_reg.txt`) count as complete for the values they name.
- `KANIT YOK` when the main state listing is missing or filtered and the related events are missing or their audit subcategory was off.
- Without a known-good baseline (same build's original binary hash, vendor list of LSA packages, software inventory), calling a binary, LSA package or installed tool "unexpected" is [DOĞRULANMAMIŞ].

Extra checks (applied if evidence exists, not counted): process whose parent is unusual (`svchost -s Schedule` → `powershell`, Office → script host); process from `%TEMP%` / `C:\Users\Public`; connection to an IOC address (`netstat.txt` + `processes.txt` by PID); Defender exclusions (`Get-MpPreference` output, if provided); BITS jobs (`Get-BitsTransfer -AllUsers`, if provided); COM hijacks in user `Software\Classes\CLSID`; Netsh helper DLLs; print monitors; W32Time time providers; Office add-ins; log clearing (1102 in `security.csv`, 104 in `system.csv`) and audit policy changes (4719, only from the optional separate export `security_extra.csv`).

## Report and Validator compatibility
- File name `reports/YYYY-MM-DD_ir_<short-name>.md`; the Validator then requires the K1–K6 table in `## Kanıt` and at least one SHA-256 there.
- Kapsam names the list with exactly this sentence (same as `SKILL.md` → Input): "Windows kalıcılık listesi uygulandı (incident-response/windows.md)". No Linux→Windows mapping table is needed; do not put one in `## Kanıt`.
- Persistence table columns: `| # | Mekanizma (Windows) | Sonuç | Dosya:satır | Gerekçe |`. Each row starts with `| K1 |` … `| K6 |` and contains exactly one of `İZ VAR`, `İZ YOK`, `KANIT YOK`. In the reasoning use wording like "kanıt yetersiz" instead of the literal result strings, so a row is never read as two results.
- Sum line under the table: `İZ VAR <a> + İZ YOK <b> + KANIT YOK <c> = 6`.
- KABUL is impossible while any row is `KANIT YOK` (the Validator blocks it).
